# Actify（バックエンド）

大学受験生の毎日の自習を、担当の講師が週ごとに計画して見守る学習管理サービス。
画面の動きと決まりごとは、モック v19（`reference/mock-v19/`）と、サービス全体のレポート（`reference/Actify-サービス全体レポート.md`）が正しい形。

この段階でできているのは **バックエンド全部**（DB・権限・ファイル置き場・計算・サーバの処理・AI・ログイン）。
画面はログインと確認用の仮の画面だけで、モック v19 の見た目の移植は次の段階。

## ローカルで動かす

```bash
pnpm install
pnpm db:verify        # 使い捨ての PostgreSQL でマイグレーション・seed・DBテスト（Docker 不要。PostgreSQL 16 のサーバが要る）
pnpm test             # 計算のテスト
pnpm typecheck && pnpm lint && pnpm build
```

Supabase につなぐとき：

```bash
supabase link --project-ref <プロジェクトのID>
supabase db push                  # supabase/migrations を本番に流す
psql "$DATABASE_URL" -f supabase/seed.sql   # デモの塾を入れる（本番の塾には流さない）
pnpm db:seed:files                # デモの PDF を Storage に置く
pnpm dev
```

## Supabase の設定（招待のメール）

招待とパスワードの決め直しのメールは、リンクを `/auth/confirm?token_hash=…&type=…` にした文面にする（`supabase/templates/`）。
標準の文面（`{{ .ConfirmationURL }}`）のままだと、トークンが URL の `#` の後ろに付いてサーバで受け取れず、初回のログインができない。

- ローカル（`supabase start`）：`supabase/config.toml` に設定済み
- 本番：Dashboard → Authentication → Email Templates の「Invite user」「Reset password」に、`supabase/templates/invite.html`・`recovery.html` の中身を貼る。
  Authentication → URL Configuration の Site URL を `NEXT_PUBLIC_SITE_URL` と同じにする。新規登録（Sign up）は切る（運営が招待する）

## AI の上限

AI を呼ぶ前に、DB の `ai_reserve` が枠を取る（塾ごとに順番に処理するので、同時に送っても超えない）。

| 上限 | 既定 | 変える所 |
| --- | --- | --- |
| 1人が同時に呼べる数 | 1件（前の返事が終わるまで次を受けない。2分たったものは止まったとみなす） | なし |
| 1人1日の回数（相談と目次の読み取り） | 30回 | `schools.ai_daily_limit_per_user` |
| 塾の月の予算 | 5,000円 | `schools.ai_monthly_budget_jpy` |
| 1人が24時間に送れる相談（AI を使わない返事も含む） | 100件 | `src/app/actions/student.ts` |

上限に達したら、相談は決まった文の返事（理由を添える）、目次の読み取りは手入力の下書きになる。返事は 1,500 字で切ってから保存し、保存できなければ成功にしない。

## 保護者への LINE（塾ごとの設定）

1. 塾が LINE 公式アカウントを作り（LINE Official Account Manager）、Messaging API を有効にする
2. LINE Developers でチャネルシークレットと、チャネルアクセストークン（長期）を出す
3. Actify の運営の画面「LINE の設定」に、ベーシックID（@…）・シークレット・トークンを入れる（`saveLineSettings`）。
   鍵は AES-256-GCM で暗号にして `school_line_channels`（service_role だけが読める）に置く
4. 画面に出る Webhook URL（`/api/line/webhook/<塾のID>`）を LINE Developers に入れて「Webhook の利用」をオン。
   応答メッセージ（自動応答）はオフにする（Actify が返事をする）
5. 講師が生徒の画面で保護者を足すと合言葉が出る。保護者は友だち追加 → 合言葉を送る → つながる

**通数の目安**：週の報告は保護者1人あたり月4〜5通。LINE の無料のプラン（月200通）で約40人、
ライト（月5,000円・5,000通）で約1,000人、スタンダード（月15,000円・30,000通）で約6,500人（料金は LINE ヤフーの公表値、2026年10月時点）。
合言葉への返事（reply）は通数に数えない。上限に達すると LINE が断るので、その週の残りは「送れなかった」で残し、運営に知らせる。

## 定期処理

| 入口 | いつ | 中身 |
| --- | --- | --- |
| `/api/cron/notifications` | 5分ごと | 時刻で決まる通知を作り（DB の `enqueue_due_notifications`）、端末に送る |
| `/api/cron/weekly-reports` | 日曜 20:00〜22:50（日本時間）に10分ごと | 保護者への週の報告。1回は240秒で手前で止め、続きを次の回が送る（送った保護者は表に残るので二度は送らない） |
| `/api/cron/billing` | 毎日 3:00（日本時間） | 在籍中の生徒の数を Stripe の数量に合わせる |

`vercel.json` に書いてある。Vercel の Cron は Hobby（無料）だと1日1回までで、5分ごとは Pro が要る（Hobby は商用にも使えない）。
Vercel 以外で動かすときは、Supabase の pg_cron + pg_net から `Authorization: Bearer <CRON_SECRET>` を付けて同じ URL を呼ぶ。
どの入口も、二度呼ばれても二重に送らない（通知は `dedupe_key`、週の報告は保護者×週、契約は Stripe の Idempotency-Key）。

## 端末への通知（Web Push）

- Android・PC のブラウザはそのまま受け取れる。**iPhone はホーム画面に追加して開いたときだけ**（iOS 16.4 以降）。画面の「この端末に通知する」は、iPhone でホーム画面に追加していなければ追加の手順を出す（`pushSupport()`）
- 「通知しない時間」（既定 23:00〜7:00、本人のタイムゾーン）は端末に送らず、明けてから送る。古くなった通知（予定の15分前の通知が30分以上前、など）は送らない。アプリの中のベルには必ず残る
- ログアウトのとき、その端末の通知を外す（共用の端末で前の人の通知が届かないように）

## 生徒の一括登録（CSV）

- 列：名前・メール（必須）、学年・志望校・学部・受験日・担当講師・副担当・保護者名・続柄。講師は名前かメールで書く（同じ名前が2人いればメールで）
- **招待メールは送らない**。Supabase の認証メールは標準のままだと1時間に2通、自前の SMTP でも既定で1時間30通までなので、まとめて送れない。
  生徒はログイン画面の「はじめての方・パスワードを忘れた方」から自分のメールでパスワードを決める（1人1通ずつ、本人が押したときに届く）
- パスワードを決めるメールも同じ上限に数えるので（届く時期が生徒ごとにばらけるだけ）、**本番では自前の SMTP（Resend・SendGrid など）を Supabase に設定し、上限を Authentication → Rate Limits で上げる**。標準のままだと1時間に2人しか始められない

## 決めたこと（違えば直します）

- **予定・勉強できる時間・面談は「暦の上の日付と時刻」で持つ**（date + time）。週のカレンダーで扱う値なので、生徒のタイムゾーン（無ければ塾のタイムゾーン）の壁時計。いつ起きたか（完了した時刻など）は UTC の timestamptz。「今日」は本人のタイムゾーンで決める（DB の `private.local_today` と `localToday`）。
- **生徒は予定を直接書き換えられない**。始める・一時停止・完了・未完了に戻す・予備時間にやり残しを入れる は DB の関数から。勉強時間はタイマーの計測（止めていた時間は数えない、5分未満は押し間違いとして予定の時間、上限は予定の3倍）。
- **ひとことは生徒本人だけが書ける**（講師が代わりに完了しても、生徒の声は書かない）。返信は講師。
- **小テストの PDF は、生徒が置き場を直接見られない**。予定に付いた版だけ、サーバが確かめてから期限つきのURLを作る（先の小テストの解答を見られないように）。
- **ファイルのパスは、その行の塾のフォルダの中だけ**（DB の制約。チャットの写真は塾と生徒のフォルダ）。期限つきURLは RLS の効かない権限で作るので、作る前にもう一度、その塾のフォルダの中かを確かめる。
- **終わった予定（記録）は動かせない・消せない**（日付・時刻・長さ・範囲・版。DB のトリガ）。直すなら「未完了に戻す」から。点数・勉強時間・ひとこと・返信は直せる。
- **AI の上限（塾の月の予算・1人1日の回数）は、塾の運営では変えられない**。サービスの運営が service_role で変える。
- **小テストの版の番号は DB が付ける**（同時に登録しても重ならない）。返信の講師・作った人も、送った値ではなくログインしている人。
- **更新・削除は行数を見る**。RLS で見えない行は 0 行で黙って通るので、0 行なら「見つかりません」を返して成功にしない。
- **面談の時間と、まだの学習予定は重ならない**。予定を入れる・動かす、面談を入れる・動かす、のどちらからでも DB で止める（同じ生徒の操作は順番に処理する）。終わった予定（記録）は見ない。面談の候補も、学習予定と重なる時間は出さない。
- **AI相談は講師にも運営にも見せない**（画面にもそう書く）。原価（ai_calls）は運営が見られる。
- **やり残しの「時間だけの予定」（予備時間など）は、週の案や候補に出さない**（モックは出していた。予備時間をやり残しとして入れ直す意味が無いため）。
- 役割を変えられるのは、まだ記録や担当が無い人だけ。記録がある人は新しいアカウントを作る。
- 講師を退会にすると、担当から外れる。
- **保護者には生徒の画面を見せない**。届くのは週の報告の文面だけ。合言葉は使い捨てで、つながったあとは無効になる。保護者からの LINE には「送信専用」と返す（塾の連絡は今までどおり塾から）。
- **週の報告の「遅れている参考書」は、講師の画面の「やや遅れ」「遅れ」と同じ計算**。先生のひとことは入れていない（入れるなら週ごとに書く欄が要る）。
- **模試の偏差値の差は、同じ会社の模試どうしだけ**出す。会社が違うと受けている人が違い、偏差値を比べられないため。
- **主担当は生徒ごとに1人**（DB で1人に保つ。主担当を外すと、残りの講師のうち先に担当になった人が主担当になる）。面談の予約は主担当と。副担当も計画・返信はできる。
- **月額の数量は在籍中（active）の生徒だけ**。休会中・退会の生徒は数えない。その代わり**休会中の生徒はログインしても使えない**（DB の `my_role` / `my_school` が空になり、アプリの入口でも断る。2026-10-05）。これが無いと、塾が生徒を「休会」にしたまま使わせて支払いを減らせた。契約が切れても生徒・講師の画面は止めない（止めるかどうかは決めてから）。
- **Stripe の契約は塾に1つ**。支払いページを作る前に Stripe に生きている契約が無いか聞き（`findLiveSubscription`）、あれば断る（Webhook が届く前に2回通って二重契約になるのを防ぐ）。別の契約の「解約」の知らせが遅れて届いても、今の契約を解約に見せない（`applySubscription`）。
- **AI の原価は「わからないときは高い側」**。時間切れ・途中で切れた・5xx は 0 円にせず見込み額のまま残す。知らないモデル名はいちばん高い単価で計算する。SDK の自動の再試行は切ってある（切ったあとに送り直すと、1回目の生成も請求されるのに記録は1回ぶんになる）。
- **通知の `url` は画面の置き場所の約束**（`/student`・`/student/schedule`・`/student/records`・`/coach/meet`・`/admin`）。画面を作るときはこのパスに合わせる（DB の関数に書いてあるので、変えるならマイグレーション）。
- **一括登録はファイルを2回受け取る**（下見と登録）。登録のときにサーバで読み直し、下見のファイルと同じか（SHA-256）を確かめる。
